Для макета достаточно ручного прохода и записи результата с версией/коммитом и снимками экрана. Для сервера нужны интеграционные проверки сессий, ролей, владения, контрактов и сбоящих адаптеров. Серверные проверки нельзя считать пройденными на фикстурах интерфейса.

Ответы LLM оцениваются отдельно от retrieval: проверяющий сравнивает состав, шаги, числа и ссылки с контекстом; фиксирует вопрос, версию рецепта, модель, параметры вызова и вердикт. Включить вопросы по шагу, отсутствующей температуре, замене ингредиента без сведений, чужому блюду и переключению рецепта. Критерий приёмки: нет неподтверждённых шагов и чисел, при нехватке контекста честное ограничение. Оценка поиска не доказывает выполнение этого критерия.

## Benchmark к КТ2

1. Зафиксировать версию/хеш корпуса, индекса, запросов и кода. Сохранить 30 запросов, покрывающих категории корпуса; формулировать как пользователь, а не копировать рецепт.
2. Уточнить критерий релевантности каждого запроса. Объединить top-20 кандидатов разных режимов в пул. Не считать любой найденный BM25 документ релевантным автоматически.
3. Разметить каждую пару 1/0 по критерию. При споре согласовать с продуктом. Для каждого запроса получить не менее трёх действительно релевантных; если в пуле мало — расширить пул, не ставить ложные положительные метки.
4. Перенести разметку, проверить все 30 запросов. Не считать пропуск неразмеченных запросов полным benchmark.
5. Рассчитать Recall@5/10/20 и MRR, сохранить результаты по каждому запросу и средние.
6. Сравнить none/stem/lemma и стартовую сетку k1={1.2,1.5,2.0}, b={0.5,0.75,1.0}; для оценки параметров использовать одинаковые данные и разметку.
7. Разобрать ошибки, включая отрицания, недостающее и влияние названия; сформулировать выводы без вымышленных улучшений.

Пул даёт частичную разметку: Recall оценивается относительно известных релевантных в пуле, а не всех потенциально релевантных в корпусе. Подбор и сравнение на одном наборе являются учебным экспериментом, не независимой оценкой обобщения.

```text
Recall@k(q) = |R_q ∩ Top_k(q)| / |R_q|
Mean Recall@k = mean по всем размеченным запросам
MRR@100 = mean(1 / rank первого релевантного в top-100)
```

Если в top-100 релевантного нет, вклад MRR равен 0. Существующий evaluate выводит имя MRR, но поиск ограничен глубиной 100; в отчёте явно писать MRR@100.

Работа с текущими инструментами, из отдельного RAG:

```powershell
python -m benchmark.make_pool --status
# Только если пул ещё не существует: следующая команда создаёт его
python -m benchmark.make_pool --modes lemma stem none -n 20
# После ручной разметки relevant в pool.csv
python -m benchmark.make_pool --apply
python -m benchmark.evaluate --mode lemma --mode stem --mode none --per-query
```

В текущем пуле уже 991 строка; не пересоздавать его без необходимости. Готовых меток нет. Не использовать `--force` поверх чужой разметки.

CLI evaluate не предоставляет сетку k1/b: для эксперимента нужен отдельный эксперимент, вызывающий `RecipeSearcher.build(corpus, mode, k1, b)` и evaluate на одном наборе. Нельзя менять параметры load и предполагать, что ранее сохранённый индекс перестроился.
