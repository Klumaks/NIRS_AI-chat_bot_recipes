# Корпус, индекс BM25 и поиск

Статус: существующий retrieval в `D:\ai-chef\ai-chef`, сверено с кодом. LLM-интеграции нет. Этот документ адаптирует отдельное описание RAG, не приписывая поиску возможности полного продукта.

## Корпус и документ

По исходному описанию источник — выгрузка povarenok.ru от 16.06.2021, датасет `rogozinushka/povarenok-recipes`. Локально подтверждены CSV-поля `url,name,ingredients`, **146 263** записи JSONL и выборка из 2 000 рецептов. Остальные статистики исходного описания здесь не считаются повторно проверенными.

Документ — один рецепт. Индексируется название и названия ингредиентов, без количеств: это соответствует поиску по продуктам и типу блюда и исключает шум единиц измерения. Дробления по шагам нет; шаги отсутствуют.

```json
{
  "id": 0,
  "title": "Густой молочно-клубничный коктейль",
  "ingredients": [
    {"name": "Молоко", "amount": "250 мл"},
    {"name": "Клубника", "amount": "200 г"},
    {"name": "Сахар", "amount": "15 г"}
  ],
  "url": "https://www.povarenok.ru/recipes/show/164365/",
  "source": "povarenok.ru"
}
```

`rag/corpus.py` читает словарь через `ast.literal_eval`, чистит пробелы, удаляет «куриное» у яиц (чтобы запрос «курица» не находил все яйца), исключает записи без названия или с менее чем двумя ингредиентами. Дубли определяются названием без регистра и множеством ингредиентов; количества не сравниваются. ID назначается по порядку сохранения, не является постоянным ID сайта.

В корпусе нет шагов, КБЖУ и времени. Сложность исключена из продуктовой модели. Ссылка не означает загрузку этих данных. Условия использования и распространения корпуса проверяются перед публикацией данных; учебное назначение не подменяет проверку.

## Предобработка

Одинаковый конвейер для запросов и документов в `rag/text.py`:

```text
нижний регистр -> ё/е -> токены [а-яa-z]+ -> короткие токены и стоп-слова
-> нормализация -> синонимы -> повторная фильтрация стоп-слов
```

- Только буквенные токены: цифры и единицы не нужны текущему поиску названий продуктов; дефис разделяет слова.
- Стоп-слова: служебные слова, единицы и обёртки вроде «рецепт», «приготовить».
- `lemma`: основной режим, `pymorphy3` приводит словоформы к начальной форме.
- `stem`: встроенный русский стеммер Портера/Snowball; при отсутствии `pymorphy3` автоматически заменяет `lemma`.
- `none`: без морфологии; остальные этапы и применимые синонимы сохраняются.
- Синонимы применяются после нормализации, например «картошка» → «картофель».

Лемматизация выбрана из-за русских падежей и числа. Стемминг может склеить «печень» и «печенье». Преимущество режимов проверяется benchmark, не объявляется заранее. В результатах указывается фактический режим после fallback.

## BM25

`rag/bm25.py` самостоятельно реализует обратный индекс; готовые поисковые индексы не используются. Хранятся списки `postings` (терм → номер документа, TF), длины, N, avgdl и IDF.

```text
IDF(t) = ln(1 + (N - DF(t) + 0.5) / (DF(t) + 0.5))
BM25(q,d) = sum(t in q) IDF(t) * TF(t,d)*(k1+1)
            / (TF(t,d) + k1*(1-b+b*len(d)/avgdl))
```

По умолчанию `k1=1.5`, `b=0.75` — стартовые параметры, не итог подбора. Обход выполняется по postings термов запроса. Без общих термов документ не попадает в выдачу. Повтор терма запроса повторно участвует в сумме. Сортировка по убыванию score, при равенстве — по внутреннему номеру. Индекс сериализуется в pickle; загружаются только доверенные локальные файлы.

## Фактический Python-интерфейс

```python
from rag.search import RecipeSearcher
searcher = RecipeSearcher.load()
hits = searcher.search("курица, рис и лук", k=5, require_all=False)
counts = searcher.count("курица, рис и лук")
```

`search(query: str, k: int | None = 5, require_all: bool = False) -> list[dict]` возвращает `id`, `title`, `ingredients`, `url`, `score`, `matched_terms`. Пустой список — нет совпадений. `k=None` возвращает все результаты. `require_all=True` требует все уникальные термы запроса в индексируемом тексте, но не запрещает дополнительные ингредиенты. `count` возвращает `any` и `all`.

`load(mode="lemma", corpus_path=...)` загружает индекс фактического режима; если индекса нет или отличается число документов, строит и сохраняет. Размер не доказывает совпадение содержимого: при обновлении корпуса индекс перестраивают с фиксацией версии.

## Запуск

Python 3.10+, отдельная папка RAG:

```powershell
Set-Location 'D:\ai-chef\ai-chef'
python tests/test_rag.py
python -m rag.search query "курица рис" --mode stem --corpus data/sample_corpus.jsonl
```

Подготовка полного корпуса при наличии исходного CSV; команды перезаписывают производные данные и не нужны для проверки SDD:

```powershell
python -m pip install -r requirements.txt
python -m rag.corpus data/raw/povarenok_recipes_2021_06_16.csv
python -m rag.search build
python -m rag.search query "курица рис лук" -k 5
python -m rag.search query "курица рис лук" --all
```

`--all` может дать большой вывод, это диагностика, не контекст LLM. Большие корпус и индексы исключены из Git отдельным `.gitignore`; при переносе нужно сохранить пример и инструкцию воспроизведения.

## Ограничения

- Отрицания не поддерживаются: «без яиц» может повысить рецепты с яйцами, так как «без» удаляется.
- Недостающие ингредиенты не штрафуются; совпадения названия также влияют на результат.
- Стемминг и синонимы объединяют разные формы и иногда продукты; `matched_terms` не является списком имеющихся ингредиентов.
- Дополнительные поля продукта обеспечиваются [проверенным набором](architecture.md#подбор-и-проверенный-набор).
- Заявленные ранее 8 мс поиска, 8 с построения и 2,5 с загрузки не воспроизведены. Новые замеры должны содержать окружение и метод; продуктовый SLA не принят.

В benchmark 30 запросов с критериями и пустыми `relevant`; 991 пара пула без меток. Качество ещё не измерено. См. [метрики и протокол](verification.md#benchmark-к-кт2).

## Управление демоданными из админки

В frontend реализован отдельный каталог IndexedDB: начальные фикстуры и добавления admin через форму/JSONL. Поля и ошибки описаны в [контрактах](contracts.md#административные-данные-rag-http-моки), проверка — SC-13. Добавление, редактирование и удаление атомарно меняют версию demo-corpus-vN, новые ID не пересекаются с существующими. Старые подборы используют снимки кандидатов своей версии, разметка настоящего benchmark не затрагивается.

Демопоиск использует сопоставление нормализованных слов, не BM25 и не LLM; его диагностика не объявляет наличие настоящего индекса. Запятая и отдельное «и» поддерживаются в запросе и метках продуктов. Рецепт без шагов можно найти, но открыть как полный рецепт нельзя. КБЖУ/время остаются null, если не переданы. Введённые дополнения не получают статус verified. Реальный корпус, собственный индекс и разметка в D:\ai-chef\ai-chef остаются отдельными. Качество демоданных не подтверждает научные метрики.

Администратор может редактировать и удалять исходные и добавленные записи. Обновление сохраняет recipe_id, создаёт новую версию записи и демодополнений; удаление исключает её из новых подборов без изменения старых снимков. Счётчик ID монотонен до полного сброса. Проверка expected_version защищает от перезаписи чужого изменения. Дубликаты проверяются по тем же правилам, что при импорте, без сравнения редактируемой записи с самой собой. Собственный Python BM25, индекс и разметка не изменены; научные метрики по этому UI не измеряются.
