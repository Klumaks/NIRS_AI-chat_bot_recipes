# Интерфейс веб-приложения

Статус: спецификация; код пока отсутствует. См. [продукт](product.md) и [сценарии](scenarios.md).

## Экраны и доступ

| Экран | Содержимое | Доступ |
| --- | --- | --- |
| Вход | Email, пароль, вход, ссылка регистрации | Гость |
| Регистрация | Email, пароль, подтверждение, создание аккаунта | Гость |
| Чат | Продукты, сообщения, предложения, фильтры, выход | `user`, `admin` |
| Рецепт | Состав, шаги, параметры, источник, вопросы | `user`, `admin` |
| Пользователи | Email, роль, дата создания; создание аккаунта с выбором `user` или `admin` | `admin` |
| Активность | Период, пользователь, события и статусы | `admin` |
| Диагностика | Этапы RAG, версия, режим, источники, LLM, ошибки | `admin` |

Администратор имеет переходы «Чат» и «Администрирование». Форма создания аккаунта содержит email, начальный пароль и обязательный выбор роли `user` или `admin`. Скрытие ссылки не заменяет серверную проверку. На телефоне карточки и фильтры располагаются последовательно.

## Чат, карточки и рецепт

До первого ввода показаны инструкция и блок «Попробуйте, например» с кнопками «Курица, рис, лук» и «Яйца и помидоры». Дублирующая строка с примером над кнопками убрана. Нажатие подставляет текст в поле; отправка выполняется отдельной кнопкой. После подбора — до пяти карточек. «Изменить продукты» отделено от поля «Вопрос по этому рецепту».

Порядок карточки: название → описание → КБЖУ на 100 г → общее время и сложность → недостающее → источник → «Открыть рецепт». Энергия подписана в ккал, Б/Ж/У — в граммах. Неизвестное — «нет данных», а не ноль.

В рецепте состав и шаги — отдельные списки. Название выбранного блюда всегда видно. Возврат сохраняет фильтры; смена блюда переключает активный контекст вопросов, сохраняя предыдущую переписку в истории.

## Фильтры

Четыре пары «от/до» для ккал, белков, жиров, углеводов на 100 г. Отдельно — максимальное общее время в минутах. «Применить» и «Сбросить». Активные ограничения видны рядом с выдачей. Ошибка диапазона подписана у поля; остальные значения сохраняются.

Подсказка: рецепт без значения активного параметра исключается. Новые продукты явно сбрасывают фильтры.

## Состояния и доступность

| Состояние | Что видит пользователь |
| --- | --- |
| Загрузка | Индикатор, блокировка повтора; рецепт остаётся читаемым |
| Пустой ввод | Просьба перечислить продукты |
| Нет блюд | Предложение изменить продукты |
| Всё отсеяно | Предложение ослабить или сбросить фильтры |
| Ошибка сервиса | Сообщение, повтор и ID запроса, без технических секретов |
| Нет шагов | Причина неполноты и источник |
| Истекла сессия | Переход ко входу, остановка защищённых операций; история остаётся на сервере |
| История пуста | Предложение начать первый подбор |
| Рецепт истории недоступен | Сохранённая переписка и снимок рецепта, объяснение и «Новый подбор» |
| Удаление чата | Подтверждение с «Отмена» и «Удалить»; при удалении открытого — пустой экран |
| Нет прав | Отказ без загрузки административных данных |

Видимые подписи полей, клавиатурная навигация и различение статусов не только цветом обязательны. После ошибки сохраняются несекретные значения, если сессия ещё действует.

## Макет КТ1

Будущий локальный макет работает без серверных аккаунтов и LLM. Постоянная надпись: «Демонстрационный режим: авторизация, ответы и журнал показаны на примерах». Переключение деморолей явно обозначено; реальные пароли не используются.

В отдельном RAG `app/demo_search_results.json` содержит реальные результаты поиска без дополнительных полей. Они сохраняют подпись «реальная выдача BM25». Добавленные шаги, КБЖУ, время, сложность, ответы и журналы подписываются как демонстрационные данные.

Нужны фикстуры для подбора с недостающим, успешных фильтров, нулевой выдачи, неизвестного параметра, отсутствия шагов, сбоя и админской диагностики. Числа фикстур не объявляются сведениями из корпуса.

Порядок показа: вход → продукты → карточки → фильтры → рецепт → вопрос → смена блюда → ошибка/пустой результат → админские экраны. Приёмка — SC-10, исходники в Git и проверенная команда запуска в README.

## Макеты Figma

[Открыть «ИИ-шеф — основные экраны»](https://www.figma.com/design/0YUxru7oLg4sNx2ZZiddqL?node-id=3-137).

Это редактируемые цветные наброски, а не интерактивный прототип или локальное приложение. Структура файла:

- **01 · Основы:** цвета, типографика Manrope, общие компоненты и примеры состояний.
- **02 · Десктоп:** вход, регистрация, пустой чат, предложения, фильтрация, выбранный рецепт и помощь при приготовлении; ширина 1440 px.
- **03 · Мобильные:** пустой чат, предложения и рецепт с вопросом; ширина 390 px. Отдельно показана нижняя панель фильтров.

Основные цвета: кремовый `#F7F3E8` для фона, шалфейный `#8FA58A` для акцентов, тёмный оливковый `#344638` для текста и основных действий. Кнопки, поля, метки, карточки и сообщения используются как экземпляры общих компонентов; контейнеры используют auto layout, цвета привязаны к переменным. Тексты и растительные векторные элементы редактируемые; фотографий нет.

Параметры блюд и ответы обозначены как демонстрационные; КБЖУ везде относятся к 100 г. Административные экраны в этом наборе не создавались.

Визуально проверены вход, регистрация, пустой чат, предложения, фильтрация и выбранный рецепт. Исправлена высота кнопок и меток после обнаруженного обрезания текста. Экран помощи, три мобильных экрана, нижняя панель фильтров и компактные состояния созданы, но их финальный визуальный просмотр не выполнен: Figma MCP вернул лимит вызовов на тарифе Starter. Их нужно осмотреть в Figma перед окончательной приёмкой дизайна.

Создание Figma-макетов не закрывает требование КТ1 о запускаемом локальном интерфейсе и не подтверждает реализацию авторизации, API или LLM.

## История и второй вариант оформления

**Целевое изменение; в существующем Figma пока не применено.** На десктопе в боковой панели под «Новый подбор» появляется список личных чатов с названиями из первого запроса продуктов и действиями удаления. На мобильном история доступна в выдвижном меню по кнопке «История». Примеры списка явно демонстрационные. Выход не удаляет историю; новый подбор других продуктов создаёт отдельную запись после отправки.

Выбранный чат выделен, порядок — по последней активности. Открытие восстанавливает состояние по SC-11, удаление требует подтверждения по SC-12. Контекст LLM и видимая история различаются: сообщения прежнего блюда доступны для чтения, но не вмешиваются в ответы по новому.

Вариант 1 сохраняет логотип-веточку и получает историю и упрощённые примеры. Для сравнения запланированы три десктопных экрана варианта 2: вход, пустой чат, рецепт. Палитра, Manrope, компоновка и продуктовые правки одинаковы. Новый знак — раскрытая книга рецептов со скрещёнными ножом и половником, в простых оливковых контурах с шалфейным акцентом. Подготовлен [редактируемый SVG](../../assets/design/logo-book.svg) для будущего общего компонента логотипа.

Повторная проверка доступа подтвердила лимит Figma MCP Starter: изменения существующих макетов, создание компонента логотипа и трёх экранов варианта 2 **не выполнены**. Ссылок на отсутствующие экраны нет; текущий [файл варианта 1](https://www.figma.com/design/0YUxru7oLg4sNx2ZZiddqL?node-id=3-137) пока показывает старый сценарий без истории. Перед передачей обновлённого дизайна нужно применить правки и визуально проверить оба варианта.
