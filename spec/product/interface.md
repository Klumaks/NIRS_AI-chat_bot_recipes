# Интерфейс веб-приложения

Статус: спецификация; код пока отсутствует. См. [продукт](product.md) и [сценарии](scenarios.md).

## Экраны и доступ

| Экран | Содержимое | Доступ |
| --- | --- | --- |
| Вход | Email, пароль, вход, ссылка регистрации | Гость |
| Регистрация | Email, пароль, подтверждение, создание аккаунта | Гость |
| Чат | Продукты, сообщения, предложения, фильтры, выход | `user`, `admin` |
| Рецепт | Состав, шаги, параметры, источник, вопросы | `user`, `admin` |
| Пользователи | Email, роль, дата создания; создание аккаунта с выбором `user` или `admin` | `admin` |
| Активность | Период, пользователь, события и статусы | `admin` |
| Диагностика | Этапы RAG, версия, режим, источники, LLM, ошибки | `admin` |

Администратор имеет переходы «Чат» и «Администрирование». Форма создания аккаунта содержит email, начальный пароль и обязательный выбор роли `user` или `admin`. Скрытие ссылки не заменяет серверную проверку. На телефоне карточки и фильтры располагаются последовательно.

## Чат, карточки и рецепт

До первого ввода показаны инструкция и пример «Курица, рис, лук». После подбора — до пяти карточек. «Изменить продукты» отделено от поля «Вопрос по этому рецепту».

Порядок карточки: название → описание → КБЖУ на 100 г → общее время и сложность → недостающее → источник → «Открыть рецепт». Энергия подписана в ккал, Б/Ж/У — в граммах. Неизвестное — «нет данных», а не ноль.

В рецепте состав и шаги — отдельные списки. Название выбранного блюда всегда видно. Возврат сохраняет фильтры; смена блюда очищает уточняющий диалог.

## Фильтры

Четыре пары «от/до» для ккал, белков, жиров, углеводов на 100 г. Отдельно — максимальное общее время в минутах. «Применить» и «Сбросить». Активные ограничения видны рядом с выдачей. Ошибка диапазона подписана у поля; остальные значения сохраняются.

Подсказка: рецепт без значения активного параметра исключается. Новые продукты явно сбрасывают фильтры.

## Состояния и доступность

| Состояние | Что видит пользователь |
| --- | --- |
| Загрузка | Индикатор, блокировка повтора; рецепт остаётся читаемым |
| Пустой ввод | Просьба перечислить продукты |
| Нет блюд | Предложение изменить продукты |
| Всё отсеяно | Предложение ослабить или сбросить фильтры |
| Ошибка сервиса | Сообщение, повтор и ID запроса, без технических секретов |
| Нет шагов | Причина неполноты и источник |
| Истекла сессия | Переход ко входу, остановка защищённых операций |
| Нет прав | Отказ без загрузки административных данных |

Видимые подписи полей, клавиатурная навигация и различение статусов не только цветом обязательны. После ошибки сохраняются несекретные значения, если сессия ещё действует.

## Макет КТ1

Будущий локальный макет работает без серверных аккаунтов и LLM. Постоянная надпись: «Демонстрационный режим: авторизация, ответы и журнал показаны на примерах». Переключение деморолей явно обозначено; реальные пароли не используются.

В отдельном RAG `app/demo_search_results.json` содержит реальные результаты поиска без дополнительных полей. Они сохраняют подпись «реальная выдача BM25». Добавленные шаги, КБЖУ, время, сложность, ответы и журналы подписываются как демонстрационные данные.

Нужны фикстуры для подбора с недостающим, успешных фильтров, нулевой выдачи, неизвестного параметра, отсутствия шагов, сбоя и админской диагностики. Числа фикстур не объявляются сведениями из корпуса.

Порядок показа: вход → продукты → карточки → фильтры → рецепт → вопрос → смена блюда → ошибка/пустой результат → админские экраны. Приёмка — SC-10, исходники в Git и проверенная команда запуска в README.
