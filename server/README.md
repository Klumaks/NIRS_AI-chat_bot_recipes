# Сервер «ИИ-шефа» (FastAPI)

Ответственный: **Интеграции** (Кельцин Никита): объединение проекта, сервер, авторизация и роли, API,
связь поиска и LLM, запуск и диагностика. Сервер реализует HTTP-контракты
[spec/tech/contracts.md](../spec/tech/contracts.md) для фронтенда и вызывает модуль поиска
[search/](../search) только через его публичный интерфейс. Код поиска, предобработка, файлы корпуса,
фронтенд и продуктовые правила сервером не меняются.

## Запуск

Python 3.10+. Команды из корня репозитория (WSL/Linux/macOS):

```bash
cd server
python -m pip install -r requirements.txt
python -m chef_server create-admin --email admin@example.com   # первый admin, пароль вводится скрыто
python -m chef_server                                          # http://127.0.0.1:8000
```

PowerShell: те же команды, `Set-Location server` вместо `cd server`.

Варианты работы с фронтендом:

1. **Один процесс.** Собрать фронтенд (`cd frontend && npm run build`); сервер раздаёт `frontend/dist`
   с SPA fallback. Открыть http://127.0.0.1:8000. Сборка production идёт без MSW.
2. **Разработка интерфейса.** Сервер на 8000, Vite на 5173 через прокси:
   `API_PROXY_TARGET=http://127.0.0.1:8000 npm run dev:api` в `frontend/`
   ([инструкция](../spec/frontend-check.md#переход-на-fastapi)). Открыть http://localhost:5173.

Проверка готовности без секретов: http://127.0.0.1:8000/api/v1/health (поиск, версия корпуса, режим,
настроена ли LLM). Описание API: http://127.0.0.1:8000/api/v1/docs.

## Корпус

Сервер вызывает `RecipeSearcher` из `search/rag`. Если собран полный корпус `search/data/corpus.jsonl`
(команды — [rag.md §11](../spec/tech/rag.md#11-как-запустить)), используется он; иначе — выборка
`sample_corpus.jsonl` из Git. **В выборке нет файла шагов:** подбор и фильтры работают, а открытие рецепта
честно возвращает `409 RECIPE_INCOMPLETE` со ссылкой на источник. Для вопросов к LLM нужен полный корпус
со `steps.jsonl`. Полный корпус занимает ≈1,5 ГБ памяти и грузится ≈6 с (данные [rag.md](../spec/tech/rag.md)).

## Данные RAG

Страница /admin/rag (фронтенд Максима) работает с каталогом сервера: записи корпуса `search/` + изменения
администратора в SQLite. После каждой успешной операции сервер собирает новый индекс функцией модуля поиска
`RecipeSearcher.build` по действующему каталогу и атомарно подменяет прежний; версия каталога —
`<версия корпуса>+admin.N`. Старые чаты продолжают работать по своей версии. Подробности — в
[архитектуре](../spec/tech/architecture.md#серверная-реализация).

Если корпус пересобран, изменения администратора для прежней версии не применяются автоматически
(ID могли измениться), а запись в каталог возвращает `409 CATALOG_STALE`. Перенос:

```bash
python -m chef_server rag-status                                  # ключи версий корпуса и число изменений
python -m chef_server rag-export --base-key "<ключ>" --out admin.jsonl
python -m chef_server rag-drop --base-key "<ключ>"
# затем загрузить admin.jsonl на /admin/rag («Проверить файл» → «Подтвердить импорт»)
```

Правки записей прежнего корпуса переносятся как полные рецепты; удаления не переносятся.

## Открытые вопросы интеграции

Решения вне зоны «Интеграции» сервер не принимает: он следует контракту, а расхождения перечислены здесь.

**Максиму (продукт и интерфейс):**
- `data_mode`: по контракту сервер отдаёт `verified`, и интерфейс пишет «проверенные данные», хотя корпус
  povarenok.ru и ввод администратора вручную не проверялись (это видно в `provenance.checked_by`).
  Нужно решение о значении и подписи.
- Порядок /admin/rag как в моках: добавленные записи — в конце. На полном корпусе это страница ≈7 700;
  нужен поиск или другой порядок списка.
- В API-режиме тексты /admin/rag («Демонстрационные данные… BM25 не вызываются», «Рецепты демокорпуса»,
  «(демо)» у шагов) не соответствуют серверу. Журнал на ширине 390 px сильно переносит описание события.

**Александре (корпус и поиск):**
- После каждой операции /admin/rag индекс собирается целиком (`RecipeSearcher.build`). На полном корпусе это
  время сборки (в rag.md — 18 с для stem) и удвоение памяти под индекс на время сборки. Ускорение возможно
  только в модуле поиска (например, метод добавления/удаления документа в индексе).
- Записи администратора индексируются как есть: правила очистки корпуса («Яйцо куриное» → «Яйцо»),
  пределы КБЖУ и времени к ним не применяются. Нужно ли их применять — решение по корпусу.

## LLM

Любой OpenAI-совместимый Chat Completions API. Настройки — в `server/.env` по образцу
[.env.example](.env.example). Без LLM (`CHEF_LLM_PROVIDER=none`) работает всё, кроме вопросов по рецепту:
они дают `503 LLM_UNAVAILABLE`, рецепт остаётся доступен. Бесплатный локальный вариант — Ollama:

```bash
ollama pull qwen2.5:7b
# server/.env
CHEF_LLM_PROVIDER=openai_compatible
CHEF_LLM_BASE_URL=http://127.0.0.1:11434/v1
CHEF_LLM_MODEL=qwen2.5:7b
```

Промпт и разбор ответа — `chef_server/llm.py`. Модель получает только выбранный рецепт и последние
сообщения его ветки; сервер оставляет в `step_numbers` лишь существующие номера шагов.

## Тесты

```bash
cd server
python -m pytest -q
```

37 интеграционных проверок: сессии и cookie, CSRF, ограничение попыток входа, роли, изоляция чатов,
фильтры, рецепт, вопросы (LLM подменяется на уровне HTTP), удаление и запоздалый ответ, журнал без текстов,
данные RAG (права, проверка, JSONL, версии, старые чаты, перезапуск, перенос), сборка индекса модулем поиска
и откат при её сбое, поиск на выборке и раздача фронтенда. Результаты — в [приёмке](../spec/tech/verification.md#приёмка-сервера-fastapi).

## Структура

```text
server/
  chef_server/
    app.py            # сборка приложения: request_id, CSRF, ошибки контракта, SPA fallback
    config.py         # настройки CHEF_* и server/.env
    db.py             # схема SQLite, транзакции
    security.py       # Argon2id, сессии, CSRF, ограничение попыток входа
    deps.py           # текущий пользователь, проверка ролей, разбор фильтров
    routes_auth.py    # /auth/*
    routes_chats.py   # /selections, /conversations, /chats
    routes_admin.py   # /admin/users, /admin/activity, /admin/requests
    routes_rag.py     # /admin/rag: список, добавление, импорт JSONL, правка, удаление
    catalog.py        # каталог: корпус + изменения администратора, версии, сборка индекса модулем поиска
    rag_input.py      # проверка рецептов и JSONL
    search_adapter.py # загрузка search/rag и каталога, ошибки поиска
    llm.py            # промпт, контекст рецепта, вызов и разбор ответа
    activity.py       # журнал и диагностика этапов, хранение 30 дней
  tests/
```
