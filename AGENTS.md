# Правила работы с «ИИ-шефом»

## Перед изменениями

1. Прочитать README, продуктовую спецификацию и документы изменяемой области.
2. Сначала описать поведение и способ проверки, затем менять код. Изменение API синхронно отражать в `spec/tech/contracts.md` и сценариях.
3. Проверять наличие компонентов: исходный RAG пока лежит отдельно в `D:\ai-chef\ai-chef`. Не выдавать локальную папку за содержимое репозитория.

## При реализации

- Сохранять собственный BM25: готовый поисковый индекс не заменяет учебное задание.
- Различать реализованное, демонстрацию и запланированное. Макет не доказывает серверную авторизацию.
- Использовать КБЖУ на 100 г; неизвестные данные не заменять нулём или выдуманными значениями.
- Проверять роли сервером. Самостоятельная регистрация создаёт только `user`; администратор может создавать аккаунты с ролью `user` или `admin`.
- Не сохранять пароли, ключи, токены, полные диалоги в Git и журнале активности.
- Изменение корпуса и ID сопровождать версией и проверкой соответствия индекса, разметки и проверенных дополнений.

## Перед завершением

1. Выполнить проверки из `spec/tech/verification.md`, относящиеся к изменению. При изменении поиска нужен benchmark; без разметки сообщать, что метрики отсутствуют.
2. Для Markdown проверить относительные ссылки, идентификаторы требований и статусы. Не писать тесты, зеркально повторяющие текст.
3. Обновить `CHANGE_HISTORY.md` фактическими изменениями, будущие задачи хранить в `spec/tasks.md`.
4. Сообщить результаты проверок и ограничения. Не придумывать команду запуска отсутствующего приложения.

Распределение ответственности указано в README. Изменения продукта согласуются с Максимом, интеграции — с Никитой, поиска и корпуса — с Александрой.
