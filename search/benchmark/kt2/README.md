## Учебный набор для показа

В documents.json лежат 30 карточек из корпуса «Поварёнка». У каждой есть учебный ID D01–D30, исходный числовой ID, URL, название, категория и состав. В questions.json собраны десять вопросов с тремя эталонными рецептами на каждый и пять вопросов без ответа в карточках. Например, Q04 про десерт из банана и шоколада допускает творожно-шоколадный десерт [D10], тарт [D11] и йогуртовое желе [D12]. Q12 спрашивает срок хранения тарта. Поиск находит его карточку, но в ней нет срока хранения.

Поиск построил индекс только по этим 30 карточкам и обработал все 15 вопросов через RecipeSearcher.search. Основной режим использует лемматизацию, сортировку по покрытию запроса и BM25 при равенстве, k1 = 1,5 и b = 0,75. Для учебной проверки выбраны k = 5 и глубина MRR = 30. В [small_results.json](small_results.json) сохранены выдачи по каждому вопросу. Для бланка берутся первые три ID из поля `ranked`. На всех десяти обычных вопросах эта тройка совпала с множеством эталонов: Recall@3 = 1,000, ошибок E1 — 0. Скрипт отдельно выводит Recall@5 и MRR@30. На десяти обычных вопросах Recall@5 = 1,000 и MRR@30 = 1,000. Вопросы-ловушки исключены из этих средних. Набор составлен из десяти троек по ингредиентам, поэтому разделить темы здесь легче, чем во всём корпусе.

## Проверка на полном корпусе

153 848 рецептов, 30 запросов, 1 048 исходных пар «запрос — рецепт». Метки 1/0 находятся в benchmark/pool.csv, списки положительных ID — в benchmark/queries.json. Ассистент выполнил первичную разметку по указанным критериям, с использованием правил по составу, категориям и названию и выборочной проверкой спорных пар. Получилось 618 положительных пар, минимум три на запрос. Независимого второго разметчика не было. Оценка относится к известным положительным примерам в пуле. Подходящие рецепты вне него могут попасть в выдачу и не получить зачёт.

| Нормализация | Ранжирование | Recall@5 | Recall@10 | Recall@20 | MRR@100 |
|---|---|---:|---:|---:|---:|
| Леммы | Покрытие + BM25 | 0,1913 | 0,3546 | 0,5931 | 0,8223 |
| Леммы | BM25 | 0,1881 | 0,3461 | 0,5842 | 0,8220 |
| Стемминг | Покрытие + BM25 | 0,2430 | 0,4443 | 0,7857 | 0,9417 |
| Стемминг | BM25 | 0,2398 | 0,4341 | 0,7444 | 0,9361 |
| Без нормализации | Покрытие + BM25 | 0,1633 | 0,2767 | 0,4736 | 0,7860 |
| Без нормализации | BM25 | 0,1633 | 0,2767 | 0,4689 | 0,7635 |

В таблице k1 = 1,5 и b = 0,75. Recall@5 показывает, какую долю всех известных подходящих рецептов поиск вернул в первых пяти позициях, с усреднением по вопросам. MRR@100 учитывает позицию первого известного подходящего рецепта. При отсутствии попадания в первых ста позициях вклад равен нулю.

Сравнение 54 конфигураций сохранено в comparison.csv. По Recall@5 на этом пуле лидирует стемминг с покрытием, k1 = 2,0 и b = 0,5. Получены 0,2464 по Recall@5 и 1,000 по MRR@100. У этой же настройки Recall@20 = 0,7356. При стандартных параметрах стемминг находит больше известных релевантных рецептов к двадцатой позиции. Параметры сравнивались на том же наборе, по которому выбран максимум. Файл full_results.csv содержит 1 620 строк с выдачей и метриками по каждому запросу и конфигурации.

## Разбор ошибок

* **Отрицание.** По запросу q21 «печенье без яиц» первые три позиции основного режима заняли «Печенье из печенья» с яичным белком, «Печенье „Снежинки“» с яйцом и «Печенье из трех ингредиентов» с яйцом. Первый результат совпал по виду блюда, но нарушил ограничение на состав. Для такого запроса нужен явный фильтр исключённых ингредиентов.
* **Частичное совпадение.** Для q04 основной режим поставил на первое место салат с домашним сыром. На втором оказался салат из помидоров и малосольных огурцов, в составе которого отсутствует сыр. MRR для вопроса равен 1, а Recall@5 — только 0,25: из четырёх известных подходящих карточек в пятёрку попала одна.
* **Ловушка.** Для Q12 BM25 вернул D11 с тартом. Высокая позиция карточки подтверждает совпадение блюда, но ответить о хранении по её содержимому невозможно. Для оценки генератора корректный ответ — прямо указать, что срок хранения в карточке не приведён.

## Как повторить

В репозитории откройте каталог `search/`, а в распакованном комплекте — каталог с `requirements.txt`. Команды ниже выполняются из этого каталога.

```sh
python -m pip install -r requirements.txt
python -m benchmark.kt2.small
python -m benchmark.make_pool --status
```

Для полного прогона нужен Python 3.11+ (`hashlib.file_digest`). Передайте каталог с исходным corpus.jsonl версии из versions.json. Скрипт использует имеющиеся индексы и строит отсутствующие. В рабочей копии полный корпус находится в соседнем проекте ai-chef:

```sh
python -m benchmark.kt2.full ../../ai-chef/data
```

При расположении корпуса внутри search/data используйте `python -m benchmark.kt2.full data`. Хеши корпуса, трёх индексов, разметки и исходников зафиксированы в versions.json. Полный корпус и бинарные индексы в архив не входят.

## Проверка ответов по бланку

1. Для каждого вопроса Q01–Q15 возьмите первые три ID из поля `ranked` в [выдаче поиска](small_results.json). Найдите соответствующие [карточки](documents.json) по `doc_id` и передайте модели вопрос и эти карточки. Эталоны остаются у проверяющего.
2. Сохраните ID и порядок переданных карточек, фактический текст контекста и ответ модели. Проверяющий сверяет ответ с [эталоном](questions.json). В графе «Документ» указывает позицию первого нужного документа: 1, 2–3 или «нет».
3. Для Q01–Q10 отметьте точный, частичный или неверный ответ. Полный ответ называет три подходящих блюда, ссылается на соответствующие карточки и сохраняет их факты. Для Q11–Q15 засчитайте отказ, если модель прямо указывает, каких сведений в карточках нет. Поиск может вернуть тематически подходящий рецепт даже для ловушки.
4. Укажите причину ошибки по бланку. E1 — поиск пропустил нужный документ в топ-3, E2 — нужный фрагмент потерян при подготовке контекста, E3 — модель проигнорировала переданный фрагмент, E4 — добавила неподтверждённый факт, E5 — дала ответ при отсутствии сведений, E6 — требуется пересмотр эталона.

Accuracy равна числу полностью правильных ответов, делённому на 10. Доля корректных отказов (Correct Rejection Rate) равна числу верных отказов, делённому на 5. Для этого набора пока сохранены результаты поиска. Для расчёта обеих метрик нужны фактические ответы командной модели.
