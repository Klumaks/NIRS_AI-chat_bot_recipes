# История изменений

## 2026-10-16 — Сервер FastAPI: авторизация и роли, API, связь поиска и LLM

- Добавлен server/ (зона «Интеграции»): маршруты /api/v1 из contracts.md на FastAPI с SQLite, включая /admin/rag. Фронтенд, моки, код поиска, файлы корпуса и индекса не изменялись.
- Авторизация и роли: Argon2id, серверные сессии в cookie HttpOnly/SameSite=Lax (в БД — SHA-256 токена), 7 суток и 24 часа без активности, CSRF по Origin/Sec-Fetch-Site и JSON, 5 неудачных входов за 15 минут → 429, первый admin командой create-admin; роли и владение проверяются сервером.
- Связь с поиском только через публичный интерфейс модуля search/: подбор, фильтры, «Не хватает», шаги; после операций /admin/rag новый индекс собирается RecipeSearcher.build и атомарно подменяется. Изменения администратора хранятся с ревизиями отдельно от корпуса, старые чаты работают по снимку своей версии.
- Связь с LLM: адаптер OpenAI-совместимого API, инструкция «только по рецепту», контекст из снимка и активной ветки с бюджетом, проверка номеров шагов, коды ошибок в диагностике.
- Запуск и диагностика: раздача frontend/dist с SPA fallback, /api/v1/health, журнал и этапы запросов без текстов и секретов (30 дней), команды create-admin, rag-status, rag-export, rag-drop.
- По контракту удалено `difficulty`, `data_mode` = `verified`; фактическое происхождение — в provenance. Открытые вопросы к продукту и поиску — в server/README.md.
- Прошли 37 проверок pytest и браузерные сценарии production-фронтенда без MSW (основной путь; /admin/rag на desktop/mobile) на сервере с выборкой корпуса. Полный корпус, реальная модель LLM и benchmark не использовались.

## 2026-10-16 — Редактирование и удаление данных RAG

- Для каждой записи /admin/rag добавлены редактирование предзаполненной общей формой и удаление с подтверждением названия. Доступны отмена и сохранение, ошибочный запрос не очищает черновик. Все исходные и добавленные записи изменяемы.
- Добавлены типизированные PUT/DELETE рецепта и проверки admin в MSW. expected_version защищает от перезаписи устаревшей записи; 404, неверные данные и дубликаты не изменяют каталог. На время обновления списка действия со строками заблокированы, чтобы повторное открытие после конфликта не брало прежнюю версию.
- Обновление сохраняет ID, пересоздаёт демодополнения и увеличивает версию корпуса; удаление исключает запись из новых подборов. Постоянный next_id не переиспользует удалённые номера, миграция учитывает сохранённые снимки. Старые чаты продолжают фильтрацию, чтение и вопросы по своей версии даже после удаления.
- Журнал показывает rag_update/rag_delete с ID записи, автором, количеством и версией без содержимого рецептов. Исходный неполный деморецепт после редактирования может участвовать в обычном подборе; служебные демонстрационные состояния сохраняют свои снимки и не восстанавливают удалённые записи в новых чатах.
- Обработаны возврат с опустевшей последней страницы и пустой каталог; общий сброс восстанавливает исходные фикстуры. Обновлены ADM-04/SC-13, контракты, архитектура, описание RAG, интерфейс, инструкция, README и серверные следующие шаги.
- Прошли typecheck, 27 Vitest/RTL/HTTP-проверок, build, все 20 Playwright-сценариев desktop/mobile и отдельный API-режим без MSW. Browser plugin not available: использован Playwright/Chromium. Осмотрены снимки редактирования и подтверждения удаления; в новом сценарии нет неожиданных ошибок приложения и переполнения страницы.
- Проверены ссылки, якоря, блоки кода и ID требований/сценариев в 11 Markdown-документах, git diff --check без ошибок. Реальные Python-корпус, BM25 и benchmark не изменены; серверная защита и научные метрики не подтверждаются моками.

## 2026-10-16 — Данные RAG в админке и разделители продуктов

- Добавлена /admin/rag: список с пагинацией, версия демокорпуса, форма рецепта, предварительная проверка и подтверждение импорта JSONL. Обработчики MSW проверяют роль admin до обработки содержимого.
- JSONL ограничен 5 МиБ/1000 записями; ошибки и дубликаты показывают строки и блокируют весь импорт. Подтверждение повторно проверяет данные в транзакции. ID назначаются без коллизий; успешная операция увеличивает версию. Неизвестные значения сохраняются как null, без шагов полный рецепт недоступен.
- Демокаталог сохраняется в IndexedDB, участвует в новых подборах и очищается общим сбросом. Старые подборы хранят снимки кандидатов своей версии; прежние аккаунты/сессии/переписка сохраняются при обновлении структуры.
- Удалены сложность из карточек, полного рецепта, фикстур и актуального API, включая происхождение и устаревшие сохранённые поля. Запятая и отдельное «и» разделяют метки продуктов; подсказка и проверки закрепляют смешанный ввод и сохранение составных названий.
- Журнал дополнен событиями добавления/импорта с автором, количеством и версией без содержимого файла. Диагностика показывает версию подбора и отсутствие настоящего индекса.
- Согласованы SDD, ADM-04/SC-13, HTTP-контракты, инструкция, README и следующие шаги серверной интеграции. Настоящий Python-корпус, собственный BM25 и benchmark не менялись; научные метрики отсутствуют.
- Прошли typecheck, 22 Vitest/RTL/HTTP-проверки, build, все 16 Playwright-сценариев desktop/mobile и отдельный API-режим без MSW. Осмотрены снимки обеих ширин, проверены отсутствие горизонтального переполнения страницы и неожиданных ошибок приложения. Исправлен тестовый переход ко входу до завершения logout; итоговый полный прогон зелёный.
- Browser plugin not available: использован существующий Playwright/Chromium. Проверены 11 Markdown-файлов: ссылки, якоря, блоки кода и связи 17 требований с 13 сценариями; git diff --check без ошибок.
